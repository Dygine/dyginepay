# Deploying Dygine Pay

Around 45 minutes end to end. Do it in this order — several steps depend on the
one before.

---

## 1. Database (Neon, free)

1. [neon.tech](https://neon.tech) → new project, region **Singapore**
2. Copy the connection string
3. Change the scheme to `postgresql+psycopg://` and keep `?sslmode=require`:

```
postgresql+psycopg://user:pass@ep-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
```

Neon's free tier auto-suspends when idle. That is fine — it wakes in under a
second and the connection pool reconnects transparently.

---

## 2. Push to GitHub

```bash
cd dygine-pay
git init && git add . && git commit -m "Dygine Pay"
git remote add origin git@github.com:you/dygine-pay.git
git push -u origin main
```

`.env` is gitignored. Confirm it did not get committed:

```bash
git ls-files | grep -c "^\.env$"     # must print 0
```

---

## 3. Render

New → Blueprint → pick the repo. `render.yaml` sets everything except the
secrets, which you fill in the dashboard:

| Variable | Value |
|---|---|
| `DATABASE_URL` | from step 1 |
| `BASE_URL` | `https://pay.dygine.com` |
| `ADMIN_EMAIL` | your email |
| `ADMIN_PASSWORD` | something long |
| `RAZORPAY_KEY_ID` | `rzp_test_…` for now |
| `RAZORPAY_KEY_SECRET` | from Razorpay |
| `RAZORPAY_WEBHOOK_SECRET` | set in step 5 |
| `RAZORPAY_MODE` | `test` |
| `BUSINESS_ADDRESS` | your real address |
| `BUSINESS_EMAIL` | `billing@dygine.com` |
| `BUSINESS_PHONE` | a reachable number |
| `BUSINESS_GSTIN` | **leave empty** until registered |
| `BUSINESS_PAN` | your PAN |

`SECRET_KEY`, `ENCRYPTION_KEY` and `INTERNAL_TASK_TOKEN` are generated by Render.
Note down `INTERNAL_TASK_TOKEN` — step 7 needs it.

**Stay on Starter ($7/mo).** Free instances sleep after 15 minutes and take ~50s
to wake, so a webhook arriving at a sleeping service times out. Razorpay retries,
so no money is lost, but the customer watches "pending" for minutes after paying.

Migrations run automatically on every deploy via the start command.

---

## 4. Domain

Render → Settings → Custom Domain → `pay.dygine.com`. Add the CNAME it gives you
at your DNS provider. TLS is issued automatically within a few minutes.

Then create the first admin:

Render → Shell:
```bash
python bootstrap.py
```

Sign in at `https://pay.dygine.com/admin`.

---

## 5. Razorpay webhook

Razorpay dashboard → Settings → Webhooks → Add New Webhook.

- **URL**: `https://pay.dygine.com/webhooks/razorpay`
- **Secret**: generate something long, and put the same value in Render as
  `RAZORPAY_WEBHOOK_SECRET`
- **Events**: `payment.captured`, `payment.failed`, `order.paid`,
  `refund.processed`

This secret is **not** your API key secret. They are different values and mixing
them up means every webhook fails verification.

---

## 6. First product and key

Admin → Products & keys → add your tool → Issue key (mode `test`).

**The secret is shown once.** Copy it straight into your tool's master admin
settings. It is stored as a SHA-256 hash and cannot be recovered — only rotated.

---

## 7. Scheduled tasks

GitHub repo → Settings → Secrets → Actions:

- `DYGINE_BASE_URL` = `https://pay.dygine.com`
- `DYGINE_INTERNAL_TOKEN` = the `INTERNAL_TASK_TOKEN` from Render

Actions tab → "dygine-pay tasks" → Run workflow, to confirm it returns 200.

---

## 8. Test payment

Still in `test` mode:

```bash
curl -u dgn_test_xxx:secret https://pay.dygine.com/v1/checkout/sessions \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: first-test" \
  -d '{"customer":{"external_id":"test_1","name":"Test PG","state_code":"29"},
       "line_items":[{"description":"Test","amount":100}]}'
```

Open the `checkout_url`, pay with UPI id `success@razorpay`.

Then check:
- Admin → Payments shows it **captured**
- Admin → Invoices has a numbered invoice, PDF opens
- Admin → Webhooks → Inbound shows the Razorpay event as applied

---

## 9. Going live

1. Complete Razorpay KYC
2. Swap `RAZORPAY_KEY_ID` / `RAZORPAY_KEY_SECRET` to `rzp_live_…`
3. Set `RAZORPAY_MODE=live`
4. Add a **live-mode webhook** in Razorpay — test and live webhooks are
   configured separately and the live one is easy to forget
5. Issue a fresh `live` API key in admin and swap it into your tool
6. Make one real ₹1 payment to yourself, then refund it from admin

---

## Health

`https://pay.dygine.com/health` checks the database too, so a process that is up
but cannot reach Neon reports `degraded` rather than lying about being fine.

## When something breaks

| Symptom | Where to look |
|---|---|
| Payment stuck at created | Admin → Webhooks → Inbound. No events means the Razorpay webhook URL or secret is wrong. |
| Your tool did not hear about a payment | Admin → Webhooks → Outbound. Dead rows have a Replay button. |
| Wallet balance looks wrong | Admin → Wallets. A drift banner means stored balance and ledger disagree — stop taking top-ups and investigate. |
| Invoice numbers skipped | Should be impossible; the sequence is locked. If it happens, check Audit log for a failed capture. |
| 500s after a deploy | Render logs. Most likely `alembic upgrade head` failed on a migration. |
